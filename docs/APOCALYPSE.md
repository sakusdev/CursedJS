# Apocalypse internals

CursedJS `apocalypse` mode is an intentionally unreasonable string encoder.

Its goal is not cryptographic protection. Its goal is to reconstruct source strings using increasingly cursed JavaScript expressions while preserving program behavior.

## 1. Coercion mines

The bootstrap alphabet begins with values JavaScript can stringify without source string literals.

| Expression family | Runtime text |
| --- | --- |
| `![] + []` | `false` |
| `!![] + []` | `true` |
| `[][[]] + []` | `undefined` |
| `+{} + []` | `NaN` |
| object coercion | `[object Object]` |

Characters are extracted by computed indexing with numbers that are themselves generated from coercion expressions.

## 2. Native-function bootstrap

The initial coercion alphabet cannot spell every useful word. In particular it lacks `p`.

CursedJS therefore accesses a RegExp constructor and stringifies it.

On the Node versions covered by CI this produces the NativeFunction form:

```text
function RegExp() { [native code] }
```

That supplies `p`.

This is intentionally runtime-dependent and is why apocalypse mode is less portable than the other modes.

## 3. Constructing global functions

With `p` available, the bootstrap alphabet can spell `escape` and `unescape`.

CursedJS obtains the `Function` constructor via an array native method and its `constructor` property, with both property names themselves generated from mined characters.

The conceptual operation is:

```js
[]["filter"]["constructor"]("return unescape")()
```

but the string literals shown above are replaced with generated character expressions in actual apocalypse output.

## 4. Mining percent

Calling legacy `escape` on a generated space yields:

```text
%20
```

Index zero is therefore a source for `%`.

Digits are generated by coercing cursed numeric expressions to strings.

Hex letters `a` through `f` are already available in the bootstrap alphabet.

## 5. Arbitrary Unicode

For a character not directly available from a mine, CursedJS converts its UTF-16 code units into generated sequences such as:

```text
%u4e16
```

No source string literal is used for the sequence itself.

The generated sequence is passed to the dynamically obtained `unescape` function.

Supplementary Unicode characters such as emoji are represented as two UTF-16 surrogate code units and reconstructed together.

## 6. Why not String.fromCodePoint?

Eldritch mode uses it as a practical fallback.

Apocalypse mode bans it because the entire point is to make the fallback itself ridiculous.

## 7. Correctness checks

CI currently exercises apocalypse mode on Node.js 20 and Node.js 22, including:

- ASCII strings
- mined characters
- characters that require fallback
- Japanese text
- emoji / surrogate pairs
- empty strings
- quoted object keys
- final one-line output
- execution equivalence
- absence of `String.fromCodePoint`

## 8. Security

None.

Obfuscation is not encryption. The generated program must contain enough information to reconstruct its strings, which means a sufficiently motivated analyst can reconstruct them too.
